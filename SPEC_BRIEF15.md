# SPEC_BRIEF15 S7.1 Transitive invalidation / staleness (minimal vertical slice)
**Stage:** S7 (research record v6 §6 / §7.5 — transitive invalidation / staleness).
**Goal:** G3 (keep findings honest: a verdict that rests on a now-stale causal dependency must stop
claiming to be live).
**Depends on:** S1 differential + SECRET validation (`runner.py`), S4/S6 FINDING producers, the
FINDING lifecycle (`lifecycle.py`).
**Authorization:** maintainer `context.md` (2026-10-22), decisions Q1–Q4, recorded at checkpoint
SEQ 88/89. GATE-1 self-approved by Opus after validating the brief against the researcher's cited
findings. **CyberGym only. NO live-target testing. No scope expansion.**

## §1 — Problem
A FINDING proven against a credential stays `reachable`/`exploited`/`reported` forever, even after
that credential is rotated (the SECRET goes `dead`). There is no causal link from a FINDING to the
SECRET it depended on, and no status that means "the thing this rested on is stale; re-verify."
S7.1 adds the **minimal vertical slice** of transitive invalidation (maintainer Q1 = Option A; the
`any_of`/`blocked_by` alternative-route DAG is deferred to a later S7.x):

1. a typed, causal `derived_from` edge `FINDING → SECRET`, written **during validation**;
2. a reversible `requires_revalidation` FINDING status;
3. a pass that, when a SECRET goes `dead`, walks `derived_from` and moves every dependent FINDING to
   `requires_revalidation` — **preserving all evidence and history** (maintainer Q2: never silently
   erase prior facts).

Researcher findings this rests on: no secret-derived FINDING exists today (`runner.py:220-240` only
advances the SECRET, attaches evidence to the SECRET, and writes `authenticates_to`); the only
FINDING producers are the reachability validators (`infra_validator.py`, `web_validator.py`), keyed
off assets, with no SECRET in scope. `derive_confidence` (`lifecycle.py:67-90`) raises on any
unmapped status. `EDGE_PAIRS` has `("FINDING","SECRET")` only under `references` (an anchor, **not**
causal — maintainer Q3 forbids reusing it as a causal dependency).

## §2 — Approach

**(a) `src/kronos/schema.py` — add the typed causal edge.** Add one key to `EDGE_PAIRS`:
`"derived_from": [("FINDING", "SECRET")]`. The DDL is auto-generated by `_rel_table_group_ddl()`
(`schema.py:138-144`) — no hand-written DDL. Do **not** change `references`. Change nothing else.

**(b) `src/kronos/lifecycle.py` — add the reversible status.** In `FINDING_TRANSITIONS`
(`lifecycle.py:47-53`) add `requires_revalidation` as an authorized target of the operational
statuses and make it reversible (maintainer Q2):
```
"reachable":            {"exploited", "discarded", "requires_revalidation"},
"exploited":            {"reported", "discarded", "requires_revalidation"},
"reported":             {"requires_revalidation"},          # was terminal; now invalidatable
"discarded":            set(),
"requires_revalidation":{"reachable", "exploited", "discarded"},
```
**Re-reporting re-earns through the gate (amended after the S7.1 attempt-1 review).**
`requires_revalidation` does **NOT** transition directly to `reported`: the existing report gate in
`advance_finding_status` (`lifecycle.py:228-231`) requires `current == "exploited"` (plus the usual
anchor/evidence), and bypassing it would silently restore a reported verdict — exactly the "do not
silently erase/restore prior facts" rule (maintainer Q2). A revalidated finding climbs back the
normal way: `requires_revalidation → reachable → exploited → reported`, re-earning each gate with
fresh evidence. This keeps the report gate unchanged (reviewer option a, not b).
(`hypothesis` unchanged.) In `derive_confidence` add, before the final `raise`:
`if status == "requires_revalidation": return 3` (hypothesis tier, `< 7` cap — stale/needs-recheck,
**not** `0`, which is the terminal `dead`/`discarded` value). `advance_finding_status` stays the
single forward chokepoint; the new table edges express both the invalidation and the
revalidation, so no table-bypass is introduced. The `requires_revalidation` transition carries **no**
evidence precondition (it is an invalidation, not a promotion — the `reported` report-gate does not
apply to it).

**(c) `src/kronos/validate/invalidation.py` (NEW) — producer + pass.**
- `record_secret_finding(engagement, secret_id: str, candidate) -> str`: the secret-derived FINDING
  producer. `finding_id = f"finding:secret-access:{secret_id}:{candidate.id}"`.
  `engagement.upsert_node("FINDING", finding_id, {"source": "secret_validator", "title":
  f"Secret {secret_id} grants access to {candidate.id} (validated)", "severity": "info",
  "status": "hypothesis"})` — do **NOT** pass `confidence`/`in_scope`/`merged_into`
  (`NODE_PROPS_FORBIDDEN`, `schema.py:212`); `status` is create-only. Then:
  `engagement.upsert_edge("derived_from", finding_id, "FINDING", secret_id, "SECRET")` (the causal
  edge); `engagement.upsert_edge("vulnerable_to", candidate.id, candidate.type, finding_id,
  "FINDING")` (asset→FINDING, the existing pattern; pair is schema-legal for API_ENDPOINT/
  CLOUD_RESOURCE); guard `advance_finding_status(engagement, finding_id, "reachable")` on current
  status `hypothesis` (idempotent, mirrors `infra_validator.py:57`). The validation proof is
  preserved as FINDING evidence: `attach_evidence(graph, engagement_dir, outcome.evidence,
  kind="validation_proof", target_type="finding", target_id=finding_id)` — pass the evidence through
  from the caller (see (d)).
- `invalidate_findings_for_dead_secret(engagement, secret_id: str) -> list[str]`: the transitive
  pass. Query `MATCH (f:FINDING)-[:derived_from]->(s:SECRET {id: $sid}) RETURN f.id, f.status`
  (bind `sid`). For each dependent FINDING whose status is a non-terminal operational status
  (`reachable`/`exploited`/`reported`), `advance_finding_status(engagement, fid,
  "requires_revalidation")`; skip `discarded` and already-`requires_revalidation` (idempotent).
  Return the invalidated finding ids. **Never** delete or mutate any node or edge other than the
  FINDING `status` (which the chokepoint changes) — EVIDENCE nodes and `evidences`/`references`/
  `derived_from` edges are left exactly as they were.

**(d) `src/kronos/validate/runner.py` — one call site only.** In the existing `if outcome.live:`
branch (after `_advance_through(graph, secret_id)`), add a single call:
`record_secret_finding(graph, secret_id, candidate)` (import from `kronos.validate.invalidation`),
passing the already-available `graph`, `secret_id`, `candidate`, and `outcome.evidence` /
`engagement_dir` for the evidence attach. **No other change to `runner.py`** — not the budget, not
`_advance_through`, not the `authenticated_not_authorized` branch, not the abstention branches.

**Trigger (maintainer Q3).** The pass is driven by the existing `SECRET → dead` transition
(`advance_secret_status`). It is **not** auto-wired into `advance_secret_status` (lifecycle stays
pure); the caller invokes `invalidate_findings_for_dead_secret(engagement, secret_id)` after a secret
is marked `dead`. No new external detector, no scope-change/deletion detector (out of this slice).

No new dependency. No `events.py` change (no new event kind in this slice). No live network in any
module (the producer/pass do pure graph I/O; tests inject fakes and assert sockets unused). No edit
to `manifest.py`, `.github/`, or `cybergym/`.

## §8 — Acceptance criteria (tests-as-rules; `tests/test_invalidation.py`)
Decide PASS/FAIL from pytest's `SUMMARY:` line, never `$?` (CLAUDE.md §3). Expected values derive
from this brief's prose, not from observed behaviour.

A. **Typed causal edge** — `"derived_from"` is a key of `EDGE_PAIRS` mapping to `[("FINDING","SECRET")]`;
   a `derived_from` FINDING→SECRET edge can be created and queried; it is a distinct label from
   `references`.
B. **Secret-derived producer** — `record_secret_finding(g, secret_id, candidate)` creates
   `finding:secret-access:<sid>:<cid>` with `status=="reachable"`, a `derived_from`→SECRET edge, a
   `vulnerable_to` candidate→FINDING edge, and an attached EVIDENCE node (+ `evidences` edge) for the
   FINDING; `confidence==9` (reachable with evidence). No forbidden column is passed to `upsert_node`.
C. **Runner wiring (hermetic)** — a live-secret validation run (fake validator/probe, no network)
   leaves a `finding:secret-access:…` FINDING with its `derived_from` edge present; abstention
   branches create no such FINDING.
D. **Status + transitions** — `FINDING_TRANSITIONS` permits `reachable→requires_revalidation`,
   `exploited→requires_revalidation`, `reported→requires_revalidation`, and
   `requires_revalidation→{reachable,exploited,discarded}` (NOT directly to `reported` — re-reporting
   goes back through the gate via `exploited`); `derive_confidence("finding","requires_revalidation",
   <any>)==3`; `advance_finding_status` performs each of these transitions without raising, and
   `requires_revalidation→reported` directly **raises** `LifecycleError` (the gate still holds). Test
   every listed transition through the chokepoint, including `reported→requires_revalidation`.
E. **Transitive invalidation** — given a SECRET with a dependent `derived_from` FINDING, after
   `advance_secret_status(g, sid, "dead")` then
   `invalidate_findings_for_dead_secret(g, sid)`, the dependent FINDING has
   `status=="requires_revalidation"` and `confidence==3`, and the returned list contains it.
F. **Evidence/history preserved** — after E, the dependent FINDING's EVIDENCE node(s), its
   `evidences` edge, and its `derived_from` edge are all still present (nothing deleted); only
   `status`/`confidence` changed.
G. **Selectivity** — a FINDING **not** `derived_from` the dead SECRET (e.g. an infra/web reachability
   FINDING) is untouched by the pass; a FINDING derived_from a *different* SECRET is untouched.
H. **Reversibility** — a `requires_revalidation` FINDING can `advance_finding_status(…, "reachable")`,
   restoring `confidence` to the reachable value (`9` with evidence, `7` without).
I. **Idempotent** — running `invalidate_findings_for_dead_secret` twice leaves `status==
   requires_revalidation` and the FINDING/edge counts unchanged, and does not raise on the already-
   invalidated finding.
J. **No live network** — monkeypatch both `socket.socket` and `socket.create_connection` to raise;
   the producer and the invalidation pass still run and update the graph; assert no socket was used.
   Assert no traffic outside the CyberGym range.
K. **Scope audit (whole window)** — `git diff --name-only 17d38a8..HEAD` ⊆ the §3 set (audit the
   whole window, not just expected files).
L. **Brief-14 seal** — `tests/test_web_validator.py` contains `BRIEF_MERGE = "17d38a8"` and uses
   `f"{BRIEF_BASE}..{BRIEF_MERGE}"` (the §2a seal landed, seal-only).
M. **No forbidden columns** — `invalidation.py` never passes `confidence`/`in_scope`/`merged_into`
   to `upsert_node`, sets `status` only at create, and changes status only via `advance_finding_status`
   (structural/source assertion).
